# Notify-Commander

> Шаблон для быстрого создания сервисов на Java 21 с поддержкой Event-Driven архитектуры и гибридным хранением данных (кэш + БД).

---

## Архитектура и модули

### 1. Модуль работы с событиями [`feature/events`](.src/main/java/com/github/rek655869/notifycommander/features/events)
Построен по шаблону **Producer-Consumer**:

* **Модель событий:** Базовый абстрактный формат событий с поддержкой сериализации для безопасной передачи через очереди и каналы связи.
* **Механизм повторной обработки:** Поддержка обертки событий для отложенного выполнения, повторных попыток при сбоях и управления лимитами ошибок.
* **Маршрутизация и обработка:** Изолированные компоненты обработки (команды), подписывающиеся на определенные типы событий с возможностью фильтрации по дополнительным условиям.
* **Диспетчер:** Автоматическая сборка всех доступных обработчиков в системе и делегирование им входящих событий.
* **Транспорт событий:** Абстракция очередей с возможностью замены транспортного слоя (по умолчанию поставляется In-Memory решение).

### 2. Модуль работы с расписанием 🛠️
* **Два фоновых потока:** Один синхронизирует расписание из Google Sheets в БД, второй проверяет кэш на наступление событий.
* **Валидация триггеров:** При наступлении события выполняется внеплановое обновление кэша и дополнительная проверка (обращением к API мессенджера или Google) для подтверждения актуальности.

### 3. Модуль работы с мессенджером 🛠️
* Абстракция для отправки сообщений (таргетированная или массовая рассылка).
* Проверка наличия сообщений и активности пользователей за указанный интервал времени.

### 4. Модуль управления пользователями 🛠️
* Единая точка доступа к данным пользователей.
* Периодическое фоновое обновление профилей информацией из внешних интеграций.

## Разработка

Проект настроен для работы в изолированном контейнере разработки (`Dev Containers: Reopen in Container`).

## Запуск

```bash
git clone https://github.com/rek655869/notify-commander
cd notify-commander

docker compose up -d --build
```
При старте приложения CommandLineProducer автоматически сгенерирует демонстрационные события (одно успешное, одно с ошибкой) для проверки работоспособности.
